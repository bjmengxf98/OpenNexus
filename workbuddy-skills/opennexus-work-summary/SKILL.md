# OpenNexus 工作总结

## 数据获取

1. 调用 `get_current_user` 和 `list_wps_files` 确定身份及数据源。
2. 调用 `get_schema` 获取实时表结构，再通过 `list_records` 读取所需日期范围内的进展、任务、项目、人员等记录。
3. 对 Link 字段继续查询关联表，把记录 ID 翻译为任务、项目和人员名称；不得把 ID 直接当业务结论。
4. 明确统计口径：自然日/工作日、起止日期、部门或个人范围、是否包含空填报和历史补录。

## 分析原则

- 只根据工具返回的数据总结，不补造进度、风险、责任人或完成时间。
- 区分“没有记录”和“没有开展工作”；前者应表述为缺少填报数据。
- 建议结构：总体概览、主要进展、任务/项目状态、风险与逾期、人员与协同、下一步建议。
- 用户要求简短时先给结论和关键数字；要求正式材料时再展开。

## 避免二次模型消耗

- 由 WorkBuddy 当前模型完成分析和文字生成。
- 如需驾驶舱数据，可调用 `get_dashboard`，默认显式传 `ai_summary=false`。
- 不通过 OpenNexus 聊天接口再次总结数据。

## 输出文档

- 用户确认内容后，可调用 `generate_document` 生成 Word、PDF 或正式公文版本。
- `generate_document` 仅负责确定性排版和文件生成；正文仍由当前 WorkBuddy 模型编写。
- 生成前确认标题、文种、署名、日期和接收对象；生成后返回可下载结果。
