# OpenNexus 每日进展

## 操作流程

1. 调用 `get_current_user`，确定当前 OpenNexus 用户、默认角色和默认 `file_id`。
2. 必要时调用 `list_wps_files` 让用户选择业务表；没有明确指定时使用默认表。
3. 调用 `get_schema` 获取实时表、字段和字段类型。按名称语义匹配“任务每日进展/每日进展/工作日志”，不得猜测 `sheet_id`、字段 ID 或选项值。
4. 若要关联任务、项目或填报人，先用 `list_records` 找到真实记录 ID：
   - Link/关联字段写记录 ID 数组，如 `["record_id"]`。
   - Contact/联系人字段写 WPS 数字 `account_id`，不能写姓名、open_id 或人员表记录 ID。
5. 新增记录始终调用 `create_records` 追加到当前有效数据末尾。不要搜索或复用历史空行；多人填报造成的旧空行保持原状。
6. 修改记录前先用 `list_records` 精确定位目标，再调用 `update_records`。存在多个候选时先让用户确认。
7. 写入后再次调用 `list_records`，按返回的记录 ID 回读关键字段，确认日期、内容和关联均正确后再报告成功。

## 内容处理

- 保留用户事实，不虚构完成状态、工时或负责人。
- 一段话包含多个独立事项时，可拆成多条记录；是否拆分不明确时先说明拟拆分结果。
- 用户只说“今天做了这些”时，日期使用当前本地日期；补填历史记录时使用用户指定日期。
- 若内容能匹配现有任务，建立关联；匹配不唯一时列出候选，不擅自选择。

## 附件

- WorkBuddy 是远程 MCP 客户端，本地文件或图片必须读取为 Base64 后调用 `upload_attachment_base64`。
- 只有文件已经位于 OpenNexus 服务端受控的临时/上传目录时，才可调用 `upload_and_attach`。
- 不把 WorkBuddy 客户端路径当成 OpenNexus 服务器路径。

## 安全要求

- 不因工具返回 `ok` 就直接宣称完成，必须回读验证。
- 删除记录必须先列明目标并获得用户明确确认，再调用 `delete_records`。
- `page_token` 必须原样使用工具返回的字符串，不能自行生成。
