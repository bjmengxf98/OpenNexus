# WorkBuddy 接入 OpenNexus MCP

[简体中文](WorkBuddy-MCP接入指南.md) · [English](WorkBuddy-MCP-Guide-EN.md)

MCP 是外部客户端调用 OpenNexus 业务能力的接口。它不会把 WorkBuddy 变成 OpenNexus 前端，也不会让 OpenNexus 主动控制 WorkBuddy。

## 服务器部署

1. 按完整仓库部署 OpenNexus，不要上传本地 `data/app.db`、`.env` 或日志。
2. 在生产虚拟环境安装 `requirements.txt`。
3. 完整重启 Python 服务；系统会自动创建 MCP 令牌与审计所需的数据表。
4. 确认反向代理将 `/mcp/` 转发到 FastAPI 服务，并使用 HTTPS。
5. 如需处理较大远程附件，应同步调整反向代理上传限制，例如 Nginx 的 `client_max_body_size`。

## 创建访问令牌

1. 登录 OpenNexus，进入“设置 → MCP 接入”。
2. 填写用途明确的客户端名称，例如 `WorkBuddy`，选择有效期和所需权限；默认只读，写入、删除、结构管理和发送消息等需主动勾选。
3. 立即复制完整令牌；明文只显示一次。
4. 每个用户、客户端和环境应使用不同令牌，不要多人共用。

创建令牌即完成事先授权，权限内的工具直接执行，不再回到 OpenNexus 逐次审批。删除业务数据需独立的删除权限，删除表结构还需同时具备结构管理权限；未授权的调用直接拒绝。旧全部权限令牌仍可使用且不再逐次审批，旧限权令牌不会自动扩充删除权限。历史审批单不再执行，旧审批编号不能重放操作；升级后请刷新客户端的工具列表。WorkBuddy 自身的确认策略由其客户端设置决定。

## WorkBuddy 配置

在 WorkBuddy 打开“专家 · 技能 · 连接器 → MCP 服务管理 → 配置 MCP”，新增 Streamable HTTP 服务：

```json
{
  "mcpServers": {
    "opennexus": {
      "type": "http",
      "url": "https://your-domain.example/mcp/",
      "headers": {
        "Authorization": "Bearer onx_mcp_REPLACE_WITH_YOUR_TOKEN"
      },
      "disabled": false
    }
  }
}
```

本机测试可将 URL 改为 `http://127.0.0.1:8000/mcp/`。手机端或另一台电脑必须使用能够访问服务器的 HTTPS 地址，不能填写 `localhost`。

保存后刷新连接，客户端应能列出 OpenNexus 工具。具体工具数量会随版本变化，不应以固定数字判断连接是否正常。

## 业务执行与本系统的一致性

WorkBuddy 自行理解目标、分析和组织答复，不会再调用一轮 OpenNexus 对话模型。相同身份、相同目标和参数的记录增删改共用执行及回读核验逻辑；回答措辞和推理过程不保证一样。

- **文档位置**：生成文档使用当前令牌用户配置的文件定位本人 WPS「AI附件」，不会以业务来源表的创建人决定上传位置。每个用户仍需配置至少一个本人创建的 WPS 文件；没有定位依据时明确报错，不借用其他用户的存储空间。
- **记录写入**：`create_records`、`update_records`、`delete_records` 会执行一次写入并进行有界只读核验。`verified=true` 才表示观察到目标字段一致或目标编号已不存在；删除核验不证明该编号此前存在。`write_submitted=true` 只表示 WPS 接受请求，`null` 表示提交结果未知；`verified=false` 不代表可以重做写入，应先读取目标再判断。
- **核验边界**：每个读阶段最多 5 页、20 秒。新增前读取编号快照，以兼容 WPS 不返回新编号；只有完整且无歧义的新增编号差集才用于核验。读不到、字段表示无法严格比较、并发结果有歧义或分页未完整时，返回未确认，不重复写入。该机制不是跨请求幂等键或事务快照；外部客户端不得把未确认直接转成再次新增。
- **大表分析**：使用 `analyze_records`，明确必要字段和筛选条件，按 `next_row_offset` 续读紧凑结果，并检查 `source_is_complete`。`read_record_window`、`analyze_cached_records` 依赖本系统当前对话的内部回执，已从 MCP 工具目录移除；旧客户端调用会获得替代方式提示。升级后刷新工具列表。
- **仍有边界**：普通电子表格单元格及结构操作沿用既有接口回执，不应将其视为本次新增的记录级自动核验；OpenNexus 对话附件、话题历史也不会自动传给 WorkBuddy。需由客户端提供任务上下文与附件。本次不承诺任意指令两端已经逐项实机验收。

## 故障排查

- “需要认证”：检查 `Authorization` 是否为 `Bearer`、空格和完整令牌的组合。
- 工具数量为零：确认末尾 `/mcp/`、服务已重启，并检查反向代理是否支持流式 HTTP。
- 本机可用但手机不可用：`127.0.0.1` 只代表当前设备，应改用公网或局域网 HTTPS 地址。
- 令牌复制后无效：令牌明文只在创建时保存；列表中的缩略值不能还原完整令牌，应撤销后重新创建。

## 安全说明

- MCP 令牌的能力是用户实际权限与令牌授权范围的交集，不可越权操作。
- 怀疑泄露时立即在设置页撤销，旧令牌会失效。
- 删除、批量更新和外发消息等操作执行前应核对目标。
- 所有 MCP 调用均应进入审计日志。
- 不要在 Issue、截图、聊天记录或示例配置中提交真实令牌、域名和业务数据。
